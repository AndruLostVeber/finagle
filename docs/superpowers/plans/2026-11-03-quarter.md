# Kuro twelve-week quarter Implementation Plan

> **For agentic workers:** Use subagent-driven-development with isolated contexts and disjoint file ownership. The user explicitly selected parallel Unity/backend/UI implementation and confirmed the rules in two interview rounds.

**Goal:** Finish the existing classroom game as twelve playable workdays representing twelve weeks, with authoritative finances, progressive assistance, responsive UI, improved real 3D and honest final results.

**Architecture:** Keep Unity WebGL, the existing HTML shell and Cloudflare Durable Objects. One backend owner implements the financial state and round lifecycle; HTML never submits monetary outcomes. The LLM explains deterministic results and cannot change them.

**Tech Stack:** Unity 6000.6 built-in renderer/C#, browser HTML/CSS/JS, Workers ES modules, node:test.

**Spec:** Original attached request and confirmed rules below. This document is the shared implementation contract.

## Confirmed rules

- One workday represents one week; 12 rounds total, month closes after 4/8/12. Teacher opens rounds, starts and closes the competition. No mandatory timer.
- One company and office per participant. Teacher creates game/teams; student entry has only Join Game. Existing code required.
- All money in integer RUB at API boundary. Cash differs from accrual profit. Loans/capital are not revenue, loan repayment is not expense, equipment is capitalized. Forecast covers the entire quarter and never becomes cash.
- Initial cash/capital 2,500,000 RUB. Explicit credit up to total outstanding 1,500,000 RUB; interest 0.25% of outstanding debt at each round close, rounded to RUB. No unlimited automatic rescue. Debt survives quarter close and is disclosed.
- Reserve mandatory payments; budget is a discretionary weekly spending limit between zero and available funds after obligations. Changing it does not spend funds or consume a decision. Remainder carries in cash.
- Unaffordable optional purchases rejected. Unpaid compulsory expenses become payables; optional spending blocked while overdue. No negative cash.
- At most five confirmed business decisions per round. A multi-item equipment order is one decision. Credit/repayment count. Budget edits, hints and accounting answers do not count. Confirmations are irreversible; first accepted request wins.
- Purchases debit once on confirmation. Finish Week closes one immutable package and settles deterministic weekly activity once. LLM analysis may arrive later, preserving first valid response. Teacher advances the shared round; completed companies wait.
- Team ranking is mean forecast during play and mean actual profit at close, exact ties share rank. Include count, both values and own-team company contributions; teacher sees all companies. No private rival company state in student APIs.
- Teacher early close reports actual-to-date plus forecast separately, with early-close label; no invented future activity.
- Assistant levels: attention cue, concrete evidence, best option with explanation. User advances levels explicitly. Freeform on-topic accounting/company questions allowed. When unavailable show authored hints with fallback label; game remains usable.
- iPhone Safari / Android Chrome, 360px+, portrait supported throughout, optional landscape office. Touch drag look / tap selection. Keep existing warm cream/teal/mustard identity.
- Test Last Day enabled only by server test mode, operates on isolated clone excluded from rankings, same final-summary function; skipped rounds generate no transactions.
- Use GigaChat-3-Ultra (documented GigaChat 3:3.5); no silent substitution. Actual account/TLS access remains to be verified. No secrets in client/build/logs.

## API contract (all POST member requests carry league,id,secret)

Existing create/join/teacher routes remain. New games use economyVersion:3; old client monetary events must never alter new finance. Keep old saved games readable without silently converting their balances into real cash.

`POST /api/teams/state` -> `{game, company, round, teams, features}`.
`game`: `{code,title,status,round,totalRounds:12}`.
`company`: `{id,name,company,cash,profit,forecastProfit,debt,payables,round,budget,budgetSpent,requiredPayments,spendable,decisionCount,submitted,finished,decisions,history,summary,accounting}`.
`round`: `{number,title,brief,documents:[{id,title,text}],actions:[{id,title,description,kind,options?,items?,min?,max?,step?}],tasks:[{id,title,prompt,options:[{id,label}]}]}`.
Action kinds: `choice` (one optionId), `purchase` (itemIds array, true/false per item), `loan`/`repay` (amount). Every option/item exposes `{id,label,cost,description}`. Only server data determines costs/effects. Catalog may additionally expose explanatory labels.

`POST /api/teams/budget {round,amount,requestId}` -> full state.
`POST /api/teams/decision {round,requestId,actionId,optionId?,itemIds?,amount?}` -> full state + `change:{cash,profit,forecastProfit,reason}`.
`POST /api/teams/answer {round,requestId,taskId,optionId}` -> full state + `answer:{correct,explanation}`. Accounting separate from money and the five business decisions.
`POST /api/teams/finish {round,requestId}` -> full state. Optional choices can be skipped explicitly; finish UI warns of unresolved tasks/decisions.
`POST /api/teams/evaluation {round}` -> `{evaluation}` (fixed submitted snapshot, never arbitrary client context).
`POST /api/teams/assistant {question,level:1|2|3,taskId?}` -> `{text,source:'llm'|'fallback'|'refusal',level}`.
`POST /api/teams/test-final` -> cloned full state with `preview:true`; `features.testFinal` reflects server env flag.
`POST /api/teams/teacher {action:'advance',round}` -> teacher view. Reject stale/double advance; unfinished company must finish or teacher explicitly confirms skipping, which never invents decisions. Existing start/close/team/view remain.

Public `GET /api/teams` exposes game, team aggregate figures and counts, never secrets/private state. Authenticated state returns members only for own team. Teacher view returns all members including balances, profits, forecast and progress. Teams expose `{id,name,rank,memberCount,profit,forecastProfit,decisions,members?}`; members expose `{id,name,company,profit,forecastProfit,cash,decisions,round,submitted,updated}` to authorized viewers.

## Shared LLM module (root owns)

`src/llm.mjs` exports `answerAssistant(context,question,level,env)` and `evaluateRound(context,env)`.
Context is a credential-free snapshot `{company:{name,cash,profit,forecastProfit,debt,payables},round,decisions,history,previousForecastProfit,taskId?}`. `round` follows catalog contract above, plus optional server-authored `hints:[string,string,string]`.
Evaluation result: `{source:'llm'|'fallback',success:0..100,forecastProfit,forecastDelta,explanation,risks:[string],hints:[string]}`. Forecast values must equal deterministic snapshot. LLM requests outside DO storage lock, persisted pending marker before request, first valid evaluation wins, timeout safely retryable. Rate/size/auth checks precede provider call. Missing credentials produces labeled fallback.
